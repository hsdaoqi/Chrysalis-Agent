# Chrysalis 验证 SOP

## 核心原则

能运行就运行，能读回就读回。验证必须来自工具结果，而不是“看起来应该可以”。

## 常见产物怎么验

| 产物 | 验证动作 |
|---|---|
| Python 代码 | 运行 `pytest`，或运行最小复现命令 |
| CLI 命令 | 实际执行，检查退出码、stdout、stderr |
| JSON 输出 | 解析形状，确认关键字段存在 |
| 文件写入 | 读回文件，确认内容和路径正确 |
| 记忆/SOP | 读 L1 和目标文件，确认指针存在且没有过期能力描述 |
| 技能 | 调用技能或跑覆盖它的内核测试 |

## 对抗性检查

至少考虑一个非顺利路径：
- 空目录
- 文件不存在
- 重复运行
- 已有 skill 存在
- API Key 缺失
- 模型返回非 JSON

## 完成前检查

- 是否真的运行了命令或读回了文件？
- 是否只验证 happy path？
- 是否留下了错误的技能或过期 L1 指针？
- 是否把无法验证的内容明确说成限制？

## 输出建议

最终汇报只说关键结果：
- 改了什么
- 怎么验证的
- 还有什么限制
