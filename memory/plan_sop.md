# Chrysalis 规划 SOP

## 适用场景

满足任意一条时使用规划：
- 需要改 3 个以上文件
- 需要先理解架构再动手
- 有明显依赖顺序或失败分支
- 用户明确要求“规划”“一步步来”“按 GA 复刻”

简单读写、单个小修复、直接可验证命令，不需要单独规划。

## 规划前先探测

动手前至少确认：
- 当前目录结构
- 关键入口文件
- 已有测试
- 用户刚刚提出的约束
- L1 是否有可用 SOP 或技能

探测只读为主。涉及删除、迁移、覆盖前，先确认目标路径和影响范围。

## 计划格式

```markdown
# 任务
目标：一句话说明要完成什么
约束：用户限制、目录边界、不能破坏的东西

## 发现
- 已验证事实 1
- 已验证事实 2

## 步骤
1. [ ] 小步动作，带完成判据
2. [ ] 小步动作，带完成判据
3. [ ] 验证：运行测试或命令
```

## 执行规则

1. 一次只做一个可验证小步。
2. 每次编辑前先读相关文件。
3. 文件编辑优先用补丁，避免整文件误覆盖。
4. 做完一步马上验证局部结果。
5. 计划变化时更新计划，不凭旧印象继续。

## 验证规则

按产物选择验证：
- Python 代码：跑 `pytest` 或最小复现命令。
- CLI：实际执行命令，看 JSON、退出码、错误信息。
- 文档：读回文件，确认没有 GA 旧路径或旧工具假设。
- 记忆/SOP：确认 L1 指针存在、文件存在、内容短而准确。

## 完成标准

- 用户提出的主问题被处理。
- 相关测试或命令已跑。
- 没有新增无用技能。
- 记忆文件没有写入未经验证的信息。
