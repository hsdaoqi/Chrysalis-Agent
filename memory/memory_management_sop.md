# Chrysalis 记忆管理 SOP

## 核心原则

1. 无行动，不记忆  
   只有成功工具调用、成功技能调用、测试结果、文件读取结果可以进入长期记忆。模型猜测、计划、口头判断不能当事实写入。

2. 上层只放指针  
   `global_mem_insight.txt` 只回答“有什么可查”，不写教程、不写长解释、不写一次性任务细节。

3. 先复用，再沉淀  
   L1 已有合适技能或 SOP 时，优先调用已有内容。调用已有技能成功后，禁止再写一个重复技能。

4. 技能沉淀要克制  
   只有长链路、高成本、跨会话仍会复用、并且已有记忆无法覆盖的流程，才允许沉淀成 `skills/*.py`。

## 当前层级

```text
L1  memory/global_mem_insight.txt   极简索引和红线规则
L2  memory/global_mem.txt           经过验证、跨会话仍重要的环境事实
L3  memory/*.md / memory/*          可复用 SOP、工具说明、专项材料
L4  data/trace.log                  每次运行的结构化轨迹摘要
缓存 data/memory.json               最近任务结果摘要
```

## 各层放什么

### L1：全局索引

适合放：
- SOP 或技能的最短入口名
- 不提醒就容易犯的高代价规则
- 反直觉场景触发词

不适合放：
- 操作步骤
- 日志
- 某次任务的详细结果
- 密钥、账号、临时路径、临时状态

### L2：全局事实

只记录经过工具验证、跨会话仍重要的环境事实。当前项目通常不需要频繁写 L2。

### L3：SOP 和专项材料

适合放：
- 难以重新推导的操作约束
- 跨会话会反复用到的检查清单
- 与 Chrysalis 自身能力相关的规则

不适合放：
- 大段通用教程
- 一次性调试过程
- 几步工具调用就能重建的信息

### L4：运行轨迹

`data/trace.log` 一行一条 JSON，只记录任务、是否成功、轮数、工具数、技能数、是否写入技能。它服务于后续反思和去重，不直接注入模型上下文。

`data/memory.json` 是最近任务摘要缓存，由代码自动维护，不作为长期事实库手写维护。

摘要规则：400 字以内保留全文；超过 400 字时保留前 200 字和后 200 字，中间用省略号连接。

## 修改流程

1. 先确认信息来源是否经过工具验证。
2. 判断应该进入 L1、L2、L3 还是只留在 trace。
3. 修改 L1 时只做小补丁，保持 30 行以内。
4. 新增 SOP 后，在 L1 只加文件名或短触发词。
5. 删除或重命名 L3 文件时，同步检查 L1 指针。

## 快速判断

```text
环境或任务事实？ -> L2 或 trace
可复用操作约束？ -> L3 SOP
高频入口或红线？ -> L1
普通过程、猜测、一次性结果？ -> 不记忆
```
